# Cognitive root-cause diagnostic — 2026-10-13

## Conclusions

The remaining problems do not have one “opinion memory” cause. The traces identify three different mechanisms:

1. **Intent/category and scope confusion before contribution.** A present request for a preference about an imagined object can be labeled an imagined speech act. Structural interpretation then omits the request act, so no answer goal is formed. Other requests about an object owned by the assistant become questions about the assistant's identity, or become artifact work. The compiler preserves those model-selected categories; it does not secretly route every naming question as an artifact.
2. **Schema-valid source selectors can be semantically invalid.** The supplied schema permits token ranges that exceed the selected message, reversed ranges, and user citations labeled as assistant positions. The compiler correctly rejects them, but the entire turn stops. The original labels, text and speakers were available to the model. This is a representation/validation gap plus model selection error, not absent history.
3. **A retrospective premise is not checked by source-existence validation.** The retained overstatement first appears in contribution despite sufficient history; realization preserves it. However, varied new cases often correctly distinguish stronger support from a changed recommendation. A neighboring failure is contribution's classification of assistant-history reasoning as `about_the_user`, which makes supplied evidence unavailable to the answer path. The evidence supports narrow grounding/authority work, not a blanket new memory subsystem or a rule that forbids revisions.

No application fixes, prompt edits, schema edits, character changes or database writes were implemented. Offline counterfactual proposals are diagnostic interventions, not production changes or live-model quality results.

## Method and coverage

The predeclared main set has 17 controlled-history cases and two six-turn closed-loop scripts. Each runs with two written characters and two repeats, with identical numeric personality projections. A separately declared second wave adds four wording controls × the same characters/repeats, holding the reading-room and sailboat objects fixed after wave 1 exposed scope confusion. Neither wave changes the model prompts or pipeline.

- **84 single-turn controlled probes**, including empty histories, supplied synthetic assistant statements, genuine ambiguity, creative generation and external-action intent.
- **Eight closed-loop runs**, 36 attempted turns, 29 accepted replies; one completed all six turns. Four notebook chains stop on turn 3; three volunteer chains stop on turn 6. All planned but unexecuted turns remain recorded.
- **120 total attempted turns, 104 accepted replies.** Seven numeric-range failures, eight source-speaker failures and one policy/blocker failure stop their turns. No transport failure or realization rejection occurred in these runs.

Controlled-history fixtures are explicitly authored evidence, not claims that those seed messages were generated by the cognitive system. Their cognitive state is initialized for the probe; they assess interpretation of supplied public statements, not hidden historical mental states. Closed-loop histories start empty and use only this system's own accepted realizations, canonical predecessors, state, goals and incrementally updated dialogue memory. Accepted acknowledgments/declines are carried forward unchanged. There are no placeholder replies, silent resets, continuation through a failed turn or live-assistant substitutions.

The process uses real `gpt-6-luna` providers with `cognitive-two-call-v1`, registry v1.9. It is an in-process diagnostic, not a frontend/worker/persistence test or an evaluation of the application's differently configured default protocol. Generic character configuration is the same frozen version-2 snapshot as the preceding evaluation; this is not a new live-DB snapshot. No live user data is read. Database/Redis endpoints are unavailable local ports, collaboration is not configured, tools are not executed, provider `store=false`, SDK retries zero, temperature zero, reasoning effort none, 60-second timeout. Missing artifact/tool availability is assessed separately from intent classification.

The standard character emphasizes honesty, compassion and conversation. The opposing character emphasizes candor, substance, independence and simple names. Numeric traits remain warmth .80, directness .62, curiosity .88, playfulness .58. We do not require either character to have a particular opinion, always disagree, sound blunt, ask a question or avoid uncertainty. Warmth, balance, brevity and stylistic hedges are not defect labels.

### Earliest failures and exact causal chain

`standard-route_watch-r1` has the complete user request in Call 1. The raw proposal's opinion embedding is `hypothetical`; its model-authored reading nevertheless says `interpretation.goal.obtain_information`. Compilation preserves both. Structural `ContextReadingRules` retains canonical act/modality rules: `interpretation_v0/rules.py` groups only direct frames into request-act families. The result lacks `interpretation.act.request_information`, while retaining `interpretation.modality.hypothetical` and the model's information-seeking goal reading. Goal formation requires the request act; only the required-response obligation survives. Call 2 has acknowledgment as its only candidate and selects it. Realization expresses the selected acknowledgment. The earliest semantic scope problem is Call 1; the first demonstrated deterministic amplifier is structural interpretation, followed by goal formation. This is not a late wording failure.

The offline `counterfactuals.py` replay uses this identical capture and raw proposal, changing only the opinion's embedding:

| Scripted intervention | Canonical result |
|---|---|
| Observed hypothetical embedding | acknowledgment; no contribution |
| Same opinion event, embedding `direct` | explicit information-request goal, contribution, `provide_information.answer` |
| Forced direct artifact event | conversational-deliverable goal, `commit_or_coordinate.decline_request` because the provider is unavailable |

These interventions isolate deterministic behavior; their scripted answer text is not evidence of Luna quality. A fourth intervention uses the actual older-break history, forces a source-linked explanation, and forwards `message:1` alongside recent position/new information despite its absence from the last-eight-message window. Thus the earlier information is available; the original missing handoff is caused by the selected route.

### Contracts and alternatives

The actual ontology defines artifact work broadly: producing/proposing/suggesting words, ideas and comparisons inside chat. It separately offers `opinion_request`; `identity_request` covers the assistant's name/role. The embedding description mixes “speaker's own act” with “imagined or conditional case.” These overlapping meanings make a current question about a hypothetical object vulnerable to the hypothetical-activation guard. An object owned by the assistant is also sometimes bound as the assistant itself. No deterministic name-keyword router was found, and the same object under preference wording reaches the correct subsystem.

This establishes category/scope confusion and a deterministic consequence, not the model's hidden reason for choosing that label. Lexical shortcut, category overlap and instruction-following variation remain alternatives. The prompts already distinguish views from artifact explanations and say to use direct for the speaker's own act; adding more examples is not demonstrated to be the smallest remedy.

**Smallest general candidate:** make the present speech act distinct from the imagined proposition, and make the requested outcome distinguish a personal judgment from a produced deliverable. If the existing embedding field is retained, its contract must consistently apply to the request act; it must not suppress a real question merely because its subject is imagined. Narrow the identity target to the agent's actual attributes rather than an object it hypothetically owns. This is a scope/intent boundary fix, not a plant-name rule.

**Neighboring risks:** globally making hypothetical frames direct could adopt quoted or imagined commands and authorize external action incorrectly. Globally making naming/comparison an opinion would break genuine generation, artifact comparison and editing. Routing all self-directed language as preference could invent identity facts. Keep explicit creative, external-action, quotation, identity and genuine-ambiguity controls.

## 2. Invalid source selectors and stopped conversations

Seven turns stop on numeric ranges: all four unchanged-map comparisons and three of four final volunteer comparisons. Eight others stop on position-role attribution: all four absent-earlier-view probes and all four notebook turn-3 follow-ups. These are separate mechanisms even though both occur at Call 1 compilation.

Exact numeric evidence: `standard-revision_same-r1` cites `message:1` with `span:2-8`, but that assistant source has seven indexed tokens, ending at 6. Its recent-position source `message:3` has eight tokens, ending at 7, yet is cited as ending at 8. Volunteer failures select ranges ending at 18 in a 16-token earlier user message, whose final index is 15. The actual Call 1 input supplies the text and indexed tokens. Errors include one-past and larger overruns; a universal “subtract one” repair is unsupported.

The supplied JSON schema accepts a regex-shaped `span_ref`; it does not bind its maximum to the selected message or enforce start ≤ end. The source-role enum and message-ref enum are independent. `continuity.dialogue_span` resolves the selected message, uses its own tokens and enforces the 600-character excerpt bound. `span_bounds` uses inclusive final-token indices and raises “span outside focus tokens” even when the selected source is an earlier message. That error name does not establish that the current focus caused the problem.

Offline contract probes, against a real captured schema and reference table:

| Probe | Schema | Compiler |
|---|---|---|
| `span:0-(N−1)` on short source | accepts | accepts |
| `span:0-N` on that same N-token source | accepts | rejects bounds |
| `span:2-1` | accepts | rejects reversed range |
| Position role attached to current user message | accepts | rejects speaker/position role |
| Whole valid-token-range citation on either long source | accepts | rejects excerpt >600 characters |
| Deliberately false midnight restatement attached to valid dawn sources | accepts | accepts restated question |

The last probe demonstrates a semantic-validation limit, not a live-model failure: existence and bounds do not prove that a restatement follows from the cited text. The compiler deliberately substitutes a valid `resolved_question` for the ordinary extractive topic/referent; it does not independently verify entailment.

Punctuation is not shown to fail universally: all four short dash/semicolon dawn probes and all eight long-source probes pass. Sources on either side of the 2,000-character forwarding threshold are supplied to Call 1. Longer whole messages are intentionally absent downstream, while selected excerpts can survive. Two long-over-threshold answers accurately limit what they can infer from their available excerpt. The long fixture has a redundant optional-pause qualification; it does not prove the system would handle every distant negation. The longer-source and older-reference behaviors should not be conflated with the numeric overruns.

The notebook failures are a causal cascade. Initial imaginary-preference turns were acknowledged without a stated preference. At turn 3, there really is no earlier assistant choice to cite. The model uses the user's original option question as `earlier_position` in 4/4 runs; one also uses another user question as `recent_position`. The missing information is a real consequence of earlier scope suppression, not a memory-loss claim. The compiler's refusal to promote user text into an assistant position is correct. In the controlled absent-view probes, only a user attribution supplies an alleged old dislike, and the same attribution error occurs 4/4.

**Smallest general candidate:** bind citation role, source identity and admissible addressing together. Assistant-position roles should admit assistant sources only; user/topic/new-information citations should retain their appropriate sources. Avoid freely invented per-message token arithmetic: candidate designs include bounded code-owned span handles or exact excerpt + source identity resolved to offsets with uniqueness checks. Keep the compiler as the final guard. These probes establish a need for a better source-address contract, not which alternative will be most efficient. Do not clamp, silently drop or substitute a citation; that can change meaning while appearing to pass.

**Neighboring risks:** enumerating all spans grows quadratically for long sources; overly coarse handles can lose negation/qualifications. Exact excerpts can be ambiguous when repeated or can fail on punctuation/paraphrase. Limiting every citation to assistant speech would break user evidence and attribution. Relaxing the current guard would turn user allegations into remembered agent opinions. A recovery attempt, if later introduced, must preserve the same state, record both attempts and prove the replacement source instead of quietly resuming a failed chain.

## 3. Stronger support versus a changed position

The retained v1.9 overstatement is inspected at its actual stages in `archived-inspection.json.gz`. `standard-revision-r1:T2` already says “I’d keep the ten minutes as a welcoming default, but not as a fixed rule.” T4 says “an optional welcome” while standing by the view. At T5, Call 1 faithfully forwards that recent statement and asks whether new information affects it; T2 is also still in contribution's actual recent window. Contribution introduces “the group’s welcoming default rather than merely optional.” At T8 it says “I’ve revised the idea that they should be merely optional”; realization preserves it.

The earliest identifiable overstatement is **contribution at T5**, repeated by the same chain at T8; this is one episode, not two independent failures. Default format and optional participation are different axes and can coexist. The earlier default is sufficient evidence that “default” was not wholly new. An alternative interpretation is that “optional welcome” at T4 softened the default, and T5 strengthened it again. That supports a narrower “more committed to this default” account, not an unqualified story that default was previously absent. There is no confirmed substantive recommendation reversal in this episode.

The source-linked question restatement is intentionally a deterministic replacement for the old topic/referent, but here its substance is faithful; it does not contain the new “merely optional” contrast. The contribution view's basis/tensions do not check historical entailment. The current view schema has text/confidence/basis/tensions, no structured delta or separately checked claim about an earlier stance. Action chooses an answer; realization preserves the selected content and its canonical confidence. The trace does not support blaming realization for inventing the old position.

New varied contrasts do not establish a recurring fabricated-change mechanism:

| Relation | New observation |
|---|---|
| Explicit unchanged paper-map position | 4/4 rejected on citation bounds before contribution; no semantic revision judgment is possible. |
| Unchanged dawn preference with qualifications | 4/4 accepted, correctly retain dawn and do not manufacture a change. |
| Same library recommendation, stronger survey support | 2/4 accurately distinguish stronger support from an unchanged recommendation. Two contribution proposals instead classify the topic as `about_the_user`: one accepted knowledge-gap answer, one policy rejection. |
| General direct-route preference, one friend-visiting detour | 4/4 accepted, correctly explain a narrower exception rather than a new general preference. |
| Outside-to-inside rehearsal after storm correction | 3/4 accepted, correctly explain a genuine reversal. One contribution classifies the topic as `about_the_user` and returns a knowledge gap. |
| No substantiated earlier assistant dislike | 4/4 rejected for citing the user's attribution as an assistant position; no fabricated retrospective answer is accepted. |
| Own-response closed-loop volunteer support | 4/4 turn-3 answers distinguish stronger support from changed recommendation. Only one final summary is reached/accepted; it accurately distinguishes continuity, support and its unexpressed hypothetical exception. |

The complete volunteer run says: “I didn’t make an exception for the urgent five-minute meeting; I only acknowledged the question, so I hadn’t stated what I’d decide in that case.” Its actual preceding response was an acknowledgment. That is coherent recognition of an absent expressed view, not an obligation to invent a decision.

A **neighboring demonstrated mechanism** is authority/category confusion in contribution. Source-linked explanations are often requested as `knowledge` and must choose among `general_knowledge`, `opinion`, `about_the_user`, `current_events` and `unanswerable`; there is no explicit source-grounded dialogue-reasoning category. Three of eight library/rehearsal probes become `about_the_user` despite receiving assistant-position sources. Their claims are empty; deterministic producers retain a knowledge gap. One policy then ignores the blocker and is rejected. The earlier evidence was in the actual input; this is not proof of a genuinely missing earlier public statement, and it is distinct from false change narration. Coherent answers can use existing general-knowledge/opinion branches, so a new category's benefit still needs implementation-time measurement.

**Smallest supported candidate:** preserve the relevant earlier/current public statements and make a proposed retrospective contrast refer to the same dimension—recommendation, scope, condition or strength of support—rather than treating the user's word “changed” as proof of a reversed position. For the demonstrated availability problem, source-grounded dialogue reasoning needs an explicit authority/subject boundary from facts about the user. The single retained overstatement supports inspecting that comparison contract; the new counts do not justify an elaborate temporal-belief subsystem, a blanket change prohibition or simply more “be consistent” instructions. Any proposed entailment check must be validated on development cases before adoption.

**Neighboring risks:** forcing literal consistency would reject justified revisions, narrower exceptions and confidence changes; forcing a delta would invent changes when there are none. Treating any quoted user attribution as old belief would create false memories. Labeling every self-reference as dialogue-grounded could invent private experiences or factual identity information. Literal wording comparison cannot reliably distinguish synonymous positions from changed scope.
